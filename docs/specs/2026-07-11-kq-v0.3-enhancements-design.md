# Design: exploring-knowledge-quadrants v0.3 Enhancements

_Date: 2026-07-11_

## Motivation — Evidence from Real Usage

Five real KQ outputs exist in the repo root (2026-04-22 → 2026-05-05). They
reveal four gaps between the skill as specified (v0.2) and the skill as used:

1. **Manual refresh workflow.** `2026-05-05-kq-ai-是個穩定可靠的測試者嗎.md` is a
   hand-rolled v2 of the 2026-04-23 map: UU items later confirmed by research
   were promoted to KK, quadrants were reshuffled, and a version/provenance
   annotation was added — entirely outside the skill. The skill has no
   re-exploration mode.
2. **Template drift.** Real outputs include a `> **Seed context:** …`
   blockquote and bold item labels; the SKILL.md templates define neither.
3. **Doc rot.** README and `tests/scenarios/shallow-rag.md` still describe a
   "five-technique UU stack"; SKILL.md v0.2 has twelve probes.
4. **No verifiability.** Shallow UU bullets carry no probe attribution, so the
   fixture criterion "UU items cover ≥3 probes" cannot be checked. There is no
   structural validation of emitted files at all. Twelve free-form sequential
   probes are also the step most likely to be silently skipped by weaker
   models running the skill.

## Goals

- **E1 — Refresh mode**: first-class re-exploration of an existing KQ file
  with explicit quadrant migration and provenance.
- **E2 — Probe worksheet + attribution**: externalize the probe stack as a
  fill-in table; tag every UU bullet with its source probe.
- **E3 — Template sync**: seed-context block and version line become part of
  the official templates.
- **E4 — Self-verification**: a stdlib-only validator script
  (`skill/scripts/validate_kq.py`) + a self-check step in Phase 3 + CI
  integration.
- **E5 — Doc drift fixes**: README, test fixtures updated to v0.3 reality;
  new refresh-mode fixture.
- **E6 — Examples showcase**: tracked example outputs move to `examples/`,
  validated in CI.

## Non-Goals

- No plugin conversion, no subagent/workflow orchestration, no probe-count
  reduction, no new flags beyond `--refresh`. (YAGNI; shallow mode's 12-probe
  stack stays — the worksheet makes it tractable, tiering is not needed yet.)

## E1 — Refresh Mode

**Invocation:** `KQ --refresh <path-to-existing-kq-file> [--depth …] [--web]`,
or natural language ("refresh this knowledge map", "更新這份四象限").

**Workflow** (inserted as a pre-phase before Phase 1):

1. **Read & parse the old file.** Extract: topic, seed context, version
   (default `v1` when absent), and all items per quadrant.
2. **Re-assessment pass.** Classify every existing item:

   | Verdict | Meaning | Action |
   |---------|---------|--------|
   | CONFIRMED | UU/UK now established knowledge | promote to KK |
   | ANSWERED | KU has been resolved | promote to KK |
   | STILL-OPEN | unchanged | keep in place |
   | AWARE-NOW | UU the user clearly knows about now | demote to KU |
   | STALE | no longer relevant | retire (listed in Migration Log only) |

   Present the verdicts as a migration table: `| Item (abbrev) | From | To | Reason |`.
3. **Fresh probe pass.** Run the normal Phase 1 probe stack for the active
   `--depth`, with the old map injected as context and the instruction:
   *surface only items absent from the old map.*
4. **Phase 2 user review** as usual (migration table + fresh items).
5. **Emit** a new file dated today, same slug. The old file is never modified.

**Output changes:**
- Metadata line gains version + provenance:
  `_<date> · depth: … · web: … · v<N+1> (refreshed from <old filename>)_`
- New final section `## 🔁 Migration Log` lists every promote/demote/retire
  with a one-line reason.
- With `--web`, add a third grounding search:
  `<topic> latest research evidence`.

## E2 — Probe Worksheet + Attribution (shallow mode)

Phase 1 shallow UU generation changes from "apply all twelve probes in
sequence" (free-form) to a mandatory intermediate **worksheet**: a 12-row
markdown table `| # | Probe | Candidate item(s) |` rendered in the draft
response before consolidation. A probe may yield `—` (nothing) — permission
to return nothing prevents forced junk items.

After consolidation, every final UU bullet ends with its source tag:
`(probe: pre-mortem)`, `(probe: JTBD)`, etc. Deep mode already attributes
personas; its TRIZ supplement items get `(9-windows)` / `(contradiction)`
tags for the same reason.

Rationale: externalized intermediate work + attribution makes skipped probes
*visible* and makes fixture pass-criteria mechanically checkable — the main
lever for reliable execution on weaker models.

## E3 — Template Sync

Both output templates (and the refresh template) gain, directly under the
metadata line, an optional seed-context blockquote:

```markdown
> **Seed context:** <verbatim or lightly edited user seed, incl. checkbox angles>
```

Included whenever the user provided more than a bare topic phrase. Item style
is standardized to `- **<short label>**: <note>` (matches all real outputs).

## E4 — Self-Verification

**Script:** `skill/scripts/validate_kq.py` — Python 3, stdlib only
(`re`, `sys`, `argparse`, `pathlib`), no PEP 723 deps needed. Ships inside
`skill/` so `npx skills add` installs it.

- `--level basic` (default): H1 starts with `# Knowledge Quadrants:`;
  metadata line matches `_YYYY-MM-DD · depth: shallow|deep · web: on|off…_`;
  all four quadrant H2 headers present exactly once with correct emoji;
  ≥3 bullets per quadrant.
- `--level full` (adds): shallow → ≥3 distinct `(probe: …)` tags in UU;
  deep → `_Personas consulted:` line + persona attribution on UU bullets;
  metadata contains `refreshed from` → `## 🔁 Migration Log` section present.

Exit 0 with `PASS` lines, exit 1 with `FAIL: <reason>` lines. Basic level
must pass on the existing v0.1/v0.2 example outputs (they predate probe
tags — that's why attribution checks live in `full`).

**SKILL.md Phase 3** gains a "Self-check before finishing" step: run
`python3 <skill-dir>/scripts/validate_kq.py <output-file> --level full`;
fix and re-emit on FAIL (max 2 retries, then report remaining failures to
the user honestly).

**CI** gains steps: validator exists + `--help` runs + basic-level pass on
every `examples/*.md`.

## E5 — Doc Drift Fixes

- README: "five-technique" → twelve-probe description, add `--refresh` to
  flags/usage, add Examples section.
- `tests/scenarios/shallow-rag.md`: probe count fixed; pass criteria updated
  to check `(probe: …)` tags (now mechanically verifiable).
- `tests/scenarios/deep-saas.md`: TRIZ supplement tag criteria updated.
- New `tests/scenarios/refresh-testing.md`: refresh-mode scenario based on the

## E6 — Examples

`git mv` the tracked `2026-04-22-kq-ai-coding-agents-replacing-software-engineers.md`
to `examples/`. The four untracked personal outputs in the repo root are left
untouched (user's call whether to publish them; suggested but not acted on).

## Design Decisions

### Why refresh emits a new file instead of editing in place
The 04-23/05-05 pair shows the user's own practice: keep both versions as an
audit trail of how understanding evolved. Provenance in the metadata line +
Migration Log preserves the chain without git archaeology.

### Why a worksheet instead of probe tiering
Twelve probes per response is heavy, but the observed v0.2 outputs show the
full stack produces high-quality results. The failure mode to defend against
is *silent probe skipping*, not cost — a visible 12-row table with permission
for empty rows fixes that directly. Tiering would reduce capability for no
observed need.

### Why the validator is stdlib-only and two-leveled
Stdlib-only means it runs anywhere the skill is installed (no uv/venv
bootstrap mid-conversation). Two levels keep old outputs (no probe tags)
CI-green while holding new outputs to the stricter contract.

### Version bump
SKILL.md `metadata.version`: `0.2` → `0.3`.

---

## Acceptance Criteria

1. `python3 skill/scripts/validate_kq.py examples/2026-04-22-kq-ai-coding-agents-replacing-software-engineers.md` → exit 0.
2. Validator `--level full` on a fixture-conformant synthetic v0.3 file → exit 0; on the same file with a quadrant header removed → exit 1 naming the header.
3. SKILL.md contains: refresh pre-phase, probe worksheet instruction, probe-tag instruction, seed-context template block, self-check step, `## 🔁 Migration Log` template, version 0.3.
4. README mentions twelve probes, `--refresh`, and links `examples/`.
5. All three scenario fixtures' pass criteria reference checkable artifacts (tags, sections) rather than unverifiable claims.
6. CI passes locally (all validation steps green).

## Post-Implementation Addendum (2026-07-11)

Implemented the same day (commits `03e724f..84445c5` on `master`); all six
acceptance criteria verified against the final tree. Review rounds added
four things beyond this spec, all consistent with its goals:

- A carried-over attribution rule for refresh mode: STILL-OPEN UU items keep
  their original attribution; pre-v0.3 items without one get
  `(probe: carried-over)`.
- Explicit routing of the refresh dedup instruction to the Deep Mode UU
  Sub-Phase (deep-mode Phase 1 has no probe stack).
- A fifth fixture, `valid-deep-refresh-v03.md`, guarding the deep+refresh
  composition in CI.
- Validator hardening: clean `FAIL` on a missing file argument, stricter
  attribution matching (CJK persona names pass, trailing prose does not),
  and fenced-code-block-aware section parsing.

The shipped `skill/SKILL.md` and `skill/scripts/validate_kq.py` are the
source of truth.
